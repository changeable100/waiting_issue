# 钟靓童的 agent 对接任务

申请书分工为整体技术路线规划。请先阅读 `docs/01_scope_and_plan.md` 和 `docs/02_contract.md`，维护团队技术路线、变量字典、成员边界与版本兼容性，不重写邹佩希的模型。

优先组织确认四项问题：tw 是否包含骑手投递等待；T2 是到柜还是入柜；取餐操作资源是否需要建模及其并发数；初始柜位占用如何采集和初始化。现在的模型分别输出投递等待、学生操作排队，并将 T2 定义为到柜。若修改口径，升级契约并统一更新前端、优化和论文。

申请书未明确数据采集与参数处理的唯一负责人，请协调指定，不要默认归给某个成员。建议其 agent 按以下交付：匿名原始观测表、字段字典、清洗记录、来源证据、按日期隔离的训练/验证划分、多日到柜轨迹、通知/步行/操作经验样本、配置版本。参考 `examples/observations_template.csv`。缺失时刻保留空值而非 0；问卷自报与仪器/现场观测来源分开。

数据成员实现 `ParameterProvider.get_config(scenario_id)` 协议或输出 registry.json 和配置，维度至少覆盖日期类型、天气、午晚峰和考试周；缺失场景显式返回缺失。文献、问卷、现场、模拟参数混用时使用 mixed 并逐字段记录来源与变换，不能只写“真实数据”。三角分布和情境系数在 `prepare_examples.py` 中仅用于生成测试数据，不是已证实的需求规律。

验收：形成团队确认的职责矩阵、指标字典和数据交付清单；确认后回传变更文档给模型维护人。整体进度区分工程已验证、真实数据待校准、系统待联调和论文待完成，不以四份开发报告代替项目结题。
