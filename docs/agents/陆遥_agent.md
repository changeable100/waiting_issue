# 陆遥的 agent 对接任务

申请书分工为排队模型应用和系统优化。本文件将优化方案研究与邹佩希的基础仿真实现分开，具体以团队确认的分工为准。

请先阅读 `docs/01_scope_and_plan.md`、`docs/02_contract.md`、`locker_model/model.py` 和 `locker_model/service.py`。现有 `compare_capacities(config, [8,16,24], seed=42, replications=20)` 只做固定分柜、同容量的敏感性对比，未实现最优容量推荐或选址。需要每柜不同容量时，复制配置分别修改 `lockers` 后调用 `predict`。

请在 `optimization/` 中实现候选配置、成本约束和多目标比较，明确优化的是 deposit_wait_min、student_queue_wait_min 还是 total_queue_wait_min。不能将骑手满柜等待的降低直接写成学生到柜排队同比降低；两者可能不同向变化。新增柜体 id 时还需定义订单到新柜的分配，已有模型没有自动转投或地理选址接口。

使用相同的到达轨迹、抽样种子及重复次数比较方案，报告平均值、分位数、时间加权占用率和满柜时间占比。真实布局建议需真实柜体位置、容量、需求分配和成本数据，当前合成配置只支持工程验证。优化模块输出方案 JSON、比较表与研究假设，不修改基础仿真的 FIFO 语义。

验收：至少三组候选，包含基线、约束和完整复现命令；如果扩容不能改善某项指标应保留结果；严禁仅根据合成结果宣称达成申请书 10% 改善目标。提供可供论文成员引用的实验版本、参数来源与局限，新增优化行为测试，并保持 `python run.py test` 通过。
