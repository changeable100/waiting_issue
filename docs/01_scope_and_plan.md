## 时序与研究问题

订单下单 T1 → 到柜 T2 → 等待柜位 → 入柜 → 通知延迟 → 学生步行 → 到柜 → 取餐操作排队 → 操作完成 T3 → 柜位释放。

申请书存在两个可兼容但需分别命名的问题：满柜使骑手无法入柜，以及学生到柜后因操作位繁忙排队。已入柜的订单不会因为“柜子满”而无法被学生取走；模型不让学生等待一个必须由自己取餐才能释放的柜位，以避免因果循环。学生在通知后出发是当前假设，不代表实测行为。

设 D 为投递等待、N 为通知延迟、R 为步行、P 为学生操作排队、S 为取餐操作，则 T3 = T2 + D + N + R + P + S。若已知 U=t1+t2+t3+t4 的上游配送总时长，则 T2=T1+U。当前 U 是输入，不负责建立骑手配送链模型。t4 在此按到柜前耗时解释，入柜瞬间操作未另计；若团队定义 t4 已包含入柜等待，必须先调整以免重复计时。

当前输入为到柜轨迹而非下单量 λ；采集成员须区分订单数和到柜数。用每日轨迹抽样保留日内集中到达结构，通知、步行、操作时长从经验样本池有放回抽样，不强制套用泊松或指数分布。当前假设这些延迟在情境内独立；真实相关性尚未建模。
