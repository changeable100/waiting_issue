# 第五步 本地网页演示开发报告

汇报人：邹佩希　日期：2026年11月7日

我已在可运行模型基础上完成本地网页演示，使模型能够通过场景选择、参数调整和图表展示进行交互检查。页面已实际接入Python仿真调用，所有当前情境均显著标记为合成数据，尚未接入真实校园观测或线上系统。

## 已完成内容

1. 提供工作日/周末、晴/雨、午/晚峰、普通/考试周的组合选择，覆盖现有16类场景。
2. 支持每柜1—200格、1—100次重复及固定随机种子输入，点击运行后更新结果；输入变化但未重跑时显示提示并保留上一轮结果条件。
3. 展示平均投递等待、平均学生取餐排队、到柜至取走总延迟，以及经验分位数、时间加权占用率和满柜时间占比。
4. 绘制单轮柜体占用阶梯曲线，标示容量与到达窗口终点。多轮汇总与首轮轨迹明确区分，避免混淆统计口径。
5. 支持导出包含输入条件、参数来源、多轮指标和首轮逐订单记录的JSON，并提供双击启动脚本。

代码交付为 `web/`、`web_server.py` 和 `Start_Demo.cmd`。使用原生HTML/CSS/JavaScript与Python标准库服务，不增加前端构建依赖。原有模型接口未改变；适配说明已更新至 `docs/03_local_web.md` 及系统成员对接文档。

## 验证证据

原有16项模型测试与新增8项网页服务测试共24项全部通过，日志为 `results/web_test_log.txt`；JavaScript语法检查通过。服务测试涵盖页面与资源、16情境列表、真实模型调用、容量变化、输入范围、未知情境、无效JSON、请求来源、文件访问限制和忙碌状态。

浏览器已检查默认场景自动加载、容量修改后重算、非法容量阻止提交和JSON导出。相同场景、20次重复、种子42时，16格平均投递等待显示0.53分钟，改为8格后为18.18分钟，曲线与占用统计同步更新，与此前合成实验一致。输入0格时显示下限提示，不触发无效仿真。导出的JSON已成功下载。界面截图为 `results/web_demo.jpg`，当前浏览器记录未见警告或错误日志。

## 适用范围与下一步

演示服务仅监听本机127.0.0.1，读取注册表配置，限制请求大小、重复次数和并发仿真数量。尚未实现公网部署、正式Flask服务、微信小程序、真实数据校准与最优容量推荐。界面具备窄屏布局样式，本轮人工检查以桌面浏览器为主，尚未完成独立移动设备验证。

下一阶段需确认研究指标口径，接收含初始占用的真实观测数据并校准，再与正式服务及优化模块联调。当前合成输出用于交互和工程检查，不能作为真实精度、校园容量建议或优化收益达标的依据。
