# 第三步 参数与成员接口报告

汇报人：邹佩希　日期：2026年11月7日

我已完成参数输入、预测调用、容量比较和留出集评价接口，并为各成员整理了可直接交给其 agent 的任务说明。核心文件为 `locker_model/adapters.py`、`service.py`、`evaluation.py` 和 `docs/agents/`。

输入统一使用带 schema_version、source_kind 和 provenance 的 JSON。到达轨迹、柜体容量及通知/步行/操作时间样本均可替换；场景参数采用精确匹配，没有参数的情境显式报错。现有16类参数均标记为 synthetic，便于开发联调，并非实地观测。

对系统成员提供 predict 调用，返回分位数、均值、柜体占用率、满柜时间占比及来源；HTTP 服务与微信小程序由系统侧封装，本轮没有实现或部署。对优化成员提供相同种子下的容量敏感性比较，未替代选址和最优配置研究。对论文成员提供逐订单记录、轨迹和 MAE/覆盖率计算工具；真实留出集尚未到位，因此没有填报实际预测误差。

王泽宇、陆遥、陈子吉、钟靓童分别有一份对接说明，明确调用方法、建议目录、需要补充的工作和验收条件。数据采集/处理的唯一负责人在申请书中未明确，已在总体技术路线对接说明中提出协调事项，没有擅自指定成员承担。

接口验证覆盖未知情境、非法重复次数和空订单场景。空订单输出均值/分位数为 null，防止前端把没有数据解释为零等待。下一步运行多场景重复实验并保存可复现证据；真实数据输入和跨成员联调留待后续共同完成。
